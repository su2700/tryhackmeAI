## ⚡ 30 秒速览

**端口告诉你「这里有服务」，指纹帮助你判断「它是什么服务」。**

任务 2 已建立组件、端口和协议的参考地图。任务 3 要确认每个开放端口背后实际运行的框架。

Nmap 的 `-sV` 可能只将 `8000` 上的服务识别为 HTTP 或 `http-alt`，也可能无法识别 `8001` 上的 gRPC 服务。仅凭这些标签，还不足以确定 AI 框架。

### 优先检查这些线索

| 线索 | 看什么？ |
| --- | --- |
| HTTP 响应头 | 产品名称、服务器标识、自定义字段 |
| JSON 响应结构 | 特有字段与嵌套格式 |
| 错误信息 | 框架命名空间、张量要求、异常类型 |
| 端点命名 | `/predict`、`/v1/models`、MLflow API 前缀等 |
| gRPC 反射 | 服务名、RPC 方法与消息结构 |
| 流量指纹 | 请求是否可能来自同一套自动化工具 |

**判断原则：** 用多个线索相互印证。通用响应头、兼容 API 格式或单次错误，都可能不足以唯一识别产品。

## 1. HTTP 响应头指纹

**一句话重点：** 响应头可能直接提供框架线索；反向代理也可能隐藏或改写它们。

### TorchServe

原文给出的响应头示例：

```http
Server: TorchServe/0.x.x
```

这是一个直接的产品身份线索。

### NVIDIA Triton

原文指出，响应中包含：

```http
NV-Status
```

原文还描述了下面的请求头：

```http
endpoint-load-metrics-format: text
```

按原文说明，Triton 可据此在响应头中返回 CPU、GPU 利用率等硬件遥测信息。

> **适用范围：** 此类响应行为需结合具体版本、功能支持与配置确认，不应视为所有 Triton 部署都具备的固定特征。

### 基于 FastAPI 的 ML 服务

原文给出的线索：

```http
server: uvicorn
```

如果同时出现 `/predict` 或 `/embeddings` 等路径，就可能是 Python ML 后端。

**注意：** Uvicorn 也能承载其他应用，因此这个响应头本身不能确认 FastAPI 或 ML 服务。

### OpenAI 兼容接口

原文列出 vLLM、LiteLLM、Ollama 等服务可能出现的线索：

- `x-request-id` 响应头。
- `/v1/models` 返回模型对象。
- JSON 中包含 `"object": "model"`。

**能说明什么？** 服务使用或兼容某种 OpenAI API 格式。

**还需确认什么？** 具体产品、底层模型与代理配置；通用请求 ID 也不是某个产品独有的特征。

## 2. API 响应结构指纹

**一句话重点：** JSON 的字段与结构能帮助缩小框架范围。

### TensorFlow Serving：模型状态

原文示例：

```json
{
  "model_version_status": [
    {
      "version": "1",
      "state": "AVAILABLE"
    }
  ]
}
```

**关注：** `model_version_status`、`version`、`state`。

### Triton：模型元数据

原文示例：

```json
{
  "name": "fraud_detector",
  "versions": ["1"],
  "platform": "tensorflow_graphdef"
}
```

**关注：** 模型名称、版本和 `platform`。

其中 `platform` 有助于判断模型的后端类型；它与承载服务的产品身份是两个相关但不同的问题。

### MLflow：错误中的命名空间

原文指出，某些错误或堆栈信息可能引用：

```text
mlflow.server
mlflow.tracking
```

即使请求失败，错误内容也可能暴露框架身份。

### OpenAI 兼容服务：模型对象

原文中的单个模型对象示例：

```json
{
  "object": "model",
  "id": "llama-3.1-8b",
  "created": 1700000000
}
```

这类结构提示服务支持 OpenAI 风格的模型对象，候选可能包括 vLLM、LiteLLM、Ollama 或自定义封装。

**记忆点：** 兼容格式能缩小范围，但不能单独确定具体框架或真实底层模型。

## 3. 错误信息指纹

**一句话重点：** 输入不符合要求时，服务可能通过报错透露内部实现。

AI 推理 API 往往要求特定张量形状与数据类型。原文的方法是：发送格式错误的数据，再阅读响应。

### 原文列出的错误线索

| 目标或场景 | 原文提到的特征 |
| --- | --- |
| TensorFlow Serving 收到不符合预期的输入 | `tensorinfo_map` |
| MLflow 收到错误请求 | `mlflow.server`、`mlflow.tracking`、`databricks` 命名空间 |
| MLflow 路径遍历相关错误 | 原文关联 `CVE-2024-1558`，称可能泄露服务器完整文件路径 |
| Databricks Mosaic AI 收到异常令牌 | `io.jsonwebtoken.IncorrectClaimException` |

> **判断提示：** 错误可能因版本、代理与配置而不同。通用 Java 异常或共享库命名空间也不一定属于单一产品；原文的「唯一」「立即确认」等表述应结合其他证据理解。

### 为什么可能返回这么多细节？

原文解释：模型开发需要详细调试信息，而部分环境上线时未关闭相关输出，因而可能暴露内部细节。

**每次先找三件事：** 框架名称、预期字段、数据类型。

## 4. 端点命名：路径本身也是线索

**一句话重点：** AI 接口常使用推理动作或模型管理相关名称。

传统 REST API 常见 `/users`、`/accounts`、`/products`；AI 接口可能出现以下路径。

### 推理相关

```text
/predict
/invocations
/infer
/generate
/embeddings
/score
```

原文指出，`/invocations` 是 SageMaker 常见的接口约定。

### 模型管理

```text
/v1/models
/v2/models
```

### 框架相关前缀

```text
/api/2.0/mlflow/
/pipeline/apis/v1beta1/
```

- 第一个前缀：MLflow 相关线索。
- 第二个前缀：Kubeflow Pipelines 相关线索。

原文建议，使用 **ffuf** 或 **feroxbuster** 做路径发现时，将这些路径加入字典。

> **字典提示：** 原文称标准 SecLists 字典不包含这些路径；实际是否包含取决于所选字典和版本，可先检查现有内容。

## 5. gRPC 指纹：查询服务自己的接口说明

**一句话重点：** 开启 gRPC 反射后，客户端可能无需预先持有接口定义，就能查询服务与消息结构。

原文参考端口：

- Triton：`8001`。
- TensorFlow Serving：`8500`。

gRPC 使用的传输与消息格式，不能像普通 REST 接口那样通过简单 HTTP 探测充分识别。

### 列出服务

```bash
grpcurl -plaintext target:8001 list
```

### 描述指定服务

```bash
grpcurl -plaintext target:8001 describe inference.GRPCInferenceService
```

**前提：** 服务允许反射访问；这里的 `-plaintext` 表示不使用 TLS。

反射结果可能提供：

- 可用服务名称。
- RPC 方法。
- 输入、输出消息与字段结构。

可以把它类比为 REST API 的 `/openapi.json`。

> **边界提醒：** 反射提供的是协议结构，不一定包含每个已部署模型实际要求的全部张量维度。模型级规格可能还需查询模型元数据或配置。

## 6. JA3 / JA4：从流量模式发现自动化行为

**一句话重点：** 请求来自不同 IP，也可能因为客户端行为相似而留下共同指纹。

原文指出，内部 AI 服务流量常来自 Python 库与 gRPC 客户端，例如 `requests`、`urllib`，其特征可能不同于人工浏览器访问。

原文以 JA3 / JA4 分析说明如何区分自动化流水线流量与人工浏览，并举出以下案例数据：

- 来自 **27 个国家、62 个 IP**。
- 某次活动中 **99% 的攻击流量**具有相同的 **JA4H** 指纹。

这些一致性可支持「使用共同自动化工具」的推断，但不能单独证明相同攻击者身份。

> **术语提示：** 原文将此节统称为 TLS 指纹。JA3 与 JA4 涉及 TLS 特征，而 **JA4H 关注 HTTP 客户端请求特征**，应注意区分。
