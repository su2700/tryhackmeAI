## ⚡ 30 秒速览

**核心概念：生产 AI 系统由多个专用服务组成，而不是只有一台模型服务器。**

侦察时，先把目标分成 5 类：

| 类别 | 它负责什么？ | 代表组件 |
| --- | --- | --- |
| 模型推理服务 | 加载模型，接受预测请求 | Triton、TensorFlow Serving、TorchServe、Ollama、vLLM |
| 编排与实验跟踪 | 管理实验、训练流程和部署 | MLflow、Kubeflow、Ray |
| 向量数据库 | 存储嵌入，支持语义搜索与 RAG | Qdrant、Weaviate、Milvus、Chroma |
| 模型注册表 | 管理模型版本、阶段与产物引用 | 模型注册服务 |
| 支撑设施 | 提供开发环境、存储和监控 | Jupyter、MinIO、Prometheus 指标端点 |

**本节目标：建立目标清单。** 先根据端口推测组件，下一节再通过指纹确认。

## 1. 为什么 AI 侦察需要另一张「地图」？

传统网络中，你可能很熟悉：

- Web：`80`、`443`。
- SSH：`22`。
- 数据库：`3306`、`5432`。

AI 基础设施还会使用其他端口、协议和专用 API。普通 HTTP 扫描器可能无法正确理解某些服务，尤其是 gRPC 服务。

**先记住：** 端口只是入口线索，不能单凭端口就确定服务身份。

## 2. 模型推理服务：AI 部署的入口

**一句话重点：** 这些框架将训练好的模型加载到内存，并提供预测接口。

### NVIDIA Triton Inference Server

一个服务可以开放 3 个不同用途的端口：

| 端口     | 用途              |
| ------ | --------------- |
| `8000` | HTTP 接口         |
| `8001` | gRPC 接口         |
| `8002` | Prometheus 监控指标 |

### TensorFlow Serving

- `8500`：gRPC。
- `8501`：HTTP。

### TorchServe

- `8080`：推理接口。
- `8081`：管理 API。
- `8082`：监控指标。

### 面向大语言模型的服务

- **Ollama：** 原文列出的端口为 `11434`，可在本地硬件上运行大语言模型。
- **vLLM：** 通常在 `8000` 提供服务，侧重高吞吐量推理。
- 两者均可提供 **OpenAI 兼容的 API 格式**。

### 为什么同时提供 HTTP 和 gRPC？

原文解释：gRPC 适合内部服务间传输大型张量数据；HTTP/REST 更便于客户端应用调用。因此，同一套推理服务可能同时支持两者。

**记忆点：** 同一个服务的多个端口，可能分别承担调用、管理与监控功能。

## 3. 编排与实验跟踪：了解整个 ML 生命周期

**一句话重点：** 这些平台连接实验设计、训练和部署，可能集中保存大量项目信息。

### MLflow Tracking Server

**原文默认端口：** `5000`。

它可记录：

- 实验。
- 超参数配置。
- 训练指标。
- 模型产物。

如果实例暴露了这些内容，就可能泄露组织的机器学习研究历史；实际可见范围取决于权限和配置。

### Kubeflow

运行在 Kubernetes 上，原文列出 Web 入口端口 `80` / `443`。

主要用于编排：

- 训练流水线。
- Notebook 服务器。
- 模型部署。

### Ray

- `8265`：Dashboard 仪表板。
- `8000`：原文列出的服务端点。

原文指出，任务 1 提及的 **ShadowRay** 活动针对的正是 Ray 仪表板。

> **配置提示：** Ray 各组件的监听端口取决于实际部署，不应把 `8000` 当作所有 Ray 功能的统一端口。

## 4. 向量数据库：理解 RAG 的数据层

**一句话重点：** 向量数据库存储嵌入，也就是文本等内容的数值表示，用于语义搜索。

原文指出，AI 聊天机器人或知识助手背后通常会有用于检索的向量存储。

| 组件 | 原文参考端口 | 协议或特点 |
| --- | --- | --- |
| Qdrant | `6333` / `6334` | HTTP / gRPC |
| Weaviate | `8080` | HTTP，包含 GraphQL 接口 |
| Milvus | `19530` | 原文表中列为 gRPC |
| Chroma | `8000` | HTTP 服务 |

### 为什么这些信息有价值？

模式（schema）与配置端点可能暴露：

- 集合和字段名称。
- 嵌入或向量化配置。
- 数据主题。

例如：

```text
集合名称：internal-hr-policies
向量维度：768
```

这可能暗示 RAG 系统正在处理内部人力资源政策。

> **推断提醒：** 名称和维度提供线索，不能单独确认具体数据内容或嵌入模型。

## 5. 模型注册表：模型资产的目录

**一句话重点：** 注册表将模型、版本、存储地址与创建者联系起来。

原文列举的模型文件格式：

```text
.pkl    .pt    .onnx    .mar
```

注册表还可能保存：

- 版本历史。
- 阶段变更：`staging`、`production`、`archived`。
- 指向云存储的产物 URI（Artifact URI）。
- 每个版本的创建者身份。

**理解方式：** 注册表是资产目录；实际模型文件也可能位于它引用的外部对象存储中。

未受保护的注册表可能让人集中了解组织的机器学习产品组合，因此原文将其视为高价值侦察目标。

## 6. 支撑设施：开发环境、存储与监控

### Jupyter Notebook

**原文参考端口：** `8888`。

原文重点描述了两类风险：

- 对外监听且未要求身份验证，可能暴露代码执行或终端能力。
- Notebook 单元格中直接保存明文凭据。

原文提到的监听参数：

```text
--ip=0.0.0.0
```

> **概念提醒：** 该参数表示监听所有网络接口，本身并不表示关闭身份验证。能否访问还取决于认证、网络和其他配置。

### MinIO

**原文参考端口：** `9000`、`9001`。

提供兼容 S3 的对象存储，常用于保存模型产物。原文指出，一些部署允许列出存储桶内容。

### Prometheus 指标端点

原文示例：

- Triton：`8002`。
- TorchServe：`8082`。
- 常见路径：`/metrics`。

可能暴露模型名称、批大小、GPU 利用率和推理延迟。

**作用：** 即使不调用推理 API，也能获得理解部署结构与负载的线索。

**一行记忆：** Notebook 凭据 → MLflow 注册表 → S3 模型文件。

## 🧪 9. 实验：Cyphira Network Scanner

**场景：** 开始 Cyphira AI 审计，实验内部子网为 `10.10.45.0/24`。

**目标：** 找到网络中的 AI 组件。

原文要求打开 **Cyphira Network Scanner** 代理，完成以下步骤。这里保留实验说明，未实际运行扫描。

### ☐ 第 1 步：扫描 AI 相关端口

```bash
nmap -p 5000,6333,6334,8000,8001,8002,8888,9000,9001 -sV 10.10.45.0/24
```

命令拆解：

- `-p`：指定端口。
- `-sV`：探测服务与版本信息。
- `10.10.45.0/24`：实验目标子网。

**这一步只记录：** 哪些主机开放了端口，以及 Nmap 返回了什么服务标识。

> 本命令只扫描参考端口中的一部分；没有发现某类服务，不等于网络中不存在该服务。

### ☐ 第 2 步：扫描传统服务，补全背景

```bash
nmap -p 22,80,443,5432 -sV 10.10.45.0/24
```

将结果与第 1 步比较：

- 哪些主机似乎只提供传统服务？
- 哪些主机可能运行 AI 基础设施？
- 是否有主机同时提供两类服务？
