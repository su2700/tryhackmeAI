## 🔎 任务 2：AI 基础设施栈

**一句话重点：** 先通过端口找到可能的 AI 服务，再进一步确认。

### 端口速查

以下为原文列出的参考端口，实际部署可以不同。

| 服务 | 原文参考端口 |
| --- | --- |
| NVIDIA Triton | `8000`、`8001`、`8002` |
| TensorFlow Serving | `8500`、`8501` |
| TorchServe | `8080`、`8081`、`8082` |
| Ollama | `11434` |
| MLflow | `5000` |
| Jupyter | `8888` |
| Qdrant / Chroma（原文合并列出） | `6333`、`6334` |

> **阅读提示：** 原文将 Qdrant 和 Chroma 放在同一行，不应据此认定两者默认端口相同。

### 实验中的扫描示例

原文称，代理 **Cyphira Network Scanner** 模拟执行了：

```bash
nmap -p 5000,6333,6334,8000,8001,8002,8888,9000,9001 -sV 10.10.45.0/24
```

- `-p`：指定扫描端口。
- `-sV`：尝试识别服务及版本。
- `10.10.45.0/24`：实验目标子网。

### 题目与答案

**Q1：扫描结果中，哪台主机在端口 8888 上运行 HTTP 服务？**

**答案：** `10.10.45.20`

**Q2：MLflow Tracking Server 默认使用哪个端口？**

**答案：** `5000`

**记忆点：** 本题中，`8888 → Jupyter 主机`，`5000 → MLflow`。

## 🪪 任务 3：识别 AI 服务指纹

**一句话重点：** 结合多个线索识别框架，不只看 Nmap 的服务横幅。

### 关注 4 类线索

1. **HTTP 响应头**：产品可能返回特有字段。
2. **JSON 结构**：字段和响应格式可能暴露框架。
3. **错误信息**：异常请求可能触发框架特有报错。
4. **gRPC 反射**：可能列出服务名称。

### 原文中的探测示例

```bash
curl http://10.10.45.15:8000/v2/models
```

原文提示关注 `platform` 字段和 `NV-Status` 响应头。

> **命令提示：** 上面的 `curl` 默认显示响应正文。若要同时查看响应头，可在实验中使用 `curl -i`。

```bash
grpcurl -plaintext 10.10.45.15:8001 list
```

这条命令用于通过 gRPC 反射列出服务。原文也提到通过格式错误的请求观察框架报错，但未提供具体请求。

### 题目与答案

**Q1：`10.10.45.15:8000` 返回哪个独特的 HTTP 响应头，表明它是 NVIDIA 产品？**

**答案：** `NV-Status`

**Q2：对 `10.10.45.15:8001` 运行 `grpcurl` 后，反射结果列出的推理服务叫什么？**

**答案：** `inference.GRPCInferenceService`

**记忆点：** 响应头和服务名都是「识别线索」。

## 📦 任务 4：枚举 AI 系统

**一句话重点：** 确认服务后，继续查看模型、存储位置、用户及凭据线索。

### 原文提取了什么？

代理 **Cyphira Data Extractor** 查询 MLflow API 和 Jupyter Notebook，收集了：

- 已注册的**模型名称与版本**。
- 指向 S3 或云存储的 **Artifact URI（产物存储地址）**。
- **贡献者用户 ID**。
- Notebook 单元格中的**明文凭据**。

### MLflow API 速查

```text
/api/2.0/mlflow/registered-models/list
/api/2.0/mlflow/model-versions/search
/api/2.0/mlflow/runs/get
```

### 题目与答案

**Q1：要获取特定模型版本的产物存储位置，应使用哪个 MLflow REST API 端点？**

**原文答案：** `/api/2.0/mlflow/model-versions/search`

**Q2：`10.10.45.20` 的 Jupyter Notebook 中，MLflow 服务账号的明文密码是什么？**

**答案：** `Cyphira-MLflow-2024!`

**记忆点：** 元数据能把「模型 → 存储 → 用户 → 凭据」连接起来。

## 🗺️ 任务 5：绘制 AI 攻击面

**一句话重点：** 把零散发现连起来，理解系统之间的依赖与潜在攻击路径。

### 原文提到的风险示例

- MLflow 漏洞，原文编号为 `CVE-2026-2635`。
- Kubeflow 仪表板未要求身份验证。
- TorchServe 模型加载相关的远程代码执行（RCE）风险。

> 上述为原文中的风险描述，未核验具体版本、漏洞编号及利用条件；不能仅凭发现某项服务就认定它存在漏洞。

### MITRE ATLAS 映射（按原文保留）

| 活动 | 原文对应的 ATLAS 编号与名称 |
| --- | --- |
| 扫描 AI 服务端口 | `AML.T0006`：主动扫描（Active Scanning） |
| 通过未受保护的 API 定位模型注册表 | `AML.T0007`：发现机器学习产物（Discover ML Artifacts） |
| 暴露的 Hugging Face 令牌／被投毒的依赖项 | `AML.T0010`：机器学习供应链入侵（ML Supply Chain Compromise） |
| 枚举 LLM 配置／API 兼容性 | `AML.T0014`：发现机器学习模型家族（Discover ML Model Family） |
| 上述活动整体所属战术 | `AML.TA0002`：侦察（Reconnaissance） |

> **概念提醒：** 发现暴露的令牌或外部依赖，是发现风险线索，本身并不证明供应链已被入侵。上表保留的是原文的教学映射。

### 题目与答案

**Q1：Cyphira 的 Notebook 含有 Hugging Face 令牌，且 `internal-kb-embedder` 模型引用外部基础模型。这些暴露的供应链依赖对应哪个 ATLAS 技术编号？**

**原文答案：** `AML.T0010`

**Q2：使用 Nmap 扫描子网、用 curl 探测端点、从 MLflow API 提取元数据，整体属于哪个 ATLAS 战术？**

**原文答案：** `AML.TA0002`

**记忆点：** `T` 表示技术，`TA` 表示战术；此处按原文答案复习。

## 🛡️ 任务 6：结构化侦察与检测

**一句话重点：** 按固定流程侦察，也要理解这些行为会留下什么痕迹。

### 5 阶段侦察流程

| 阶段 | 做什么 | 原文示例 |
| --- | --- | --- |
| 1. 被动侦察 | 从已有公开信息寻找线索 | Shodan 搜索语句、GitHub 中的 `HF_TOKEN` 搜索 |
| 2. 端口扫描 | 寻找可能的 AI 服务 | 用 Nmap 扫描 AI 常见端口 |
| 3. API 指纹识别 | 判断服务框架 | 用 curl / grpcurl 分析响应头和响应内容 |
| 4. 元数据提取 | 了解模型、存储与系统信息 | 枚举 MLflow、Triton、向量数据库、Jupyter |
| 5. 供应链审查 | 检查外部依赖 | 审查 `requirements.txt`、`Pipfile` 和容器镜像仓库 |

### 防守方可能看到什么？

**原文举例：** 某个 IP 请求了以下 MLflow API，却没有对应的 UI 会话：

```text
/api/2.0/mlflow/registered-models/list
/api/2.0/mlflow/model-versions/search
```

原文将这种脚本化访问模式与 **MLOKit** 联系起来。

> **判断提示：** 访问模式可作为调查线索；仅凭这些请求，无法唯一确定使用了哪种工具。

### 优先防护措施

**启用 MLflow 身份验证。**

原文同时列出两个环境变量：

```text
MLFLOW_TRACKING_USERNAME
MLFLOW_TRACKING_PASSWORD
```

> **配置提醒：** 不要把「设置这两个变量」直接等同于「服务端已启用身份验证」。实际配置需结合所用版本和服务端设置确认。

### 题目与答案

**Q1：SIEM 日志显示，一个没有对应 MLflow UI 会话的 IP 请求了 `/api/2.0/mlflow/registered-models/list`。这符合哪个工具的访问模式？**

**原文答案：** `MLOKit`

**Q2：防止未经身份验证访问 MLflow Tracking Server，最有效的单项快速改进是什么？**

**答案：** 启用 MLflow 身份验证。

**英文提交答案：** `Enable MLflow authentication`

**记忆点：** 有访问日志不等于能确定工具；提供客户端凭据也不等于服务端已强制认证。
