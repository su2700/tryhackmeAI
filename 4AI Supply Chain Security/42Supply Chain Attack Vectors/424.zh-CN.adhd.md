## ⚡ 30 秒速览

**模型文件之外，项目安装的软件包也是供应链入口。**

| 攻击 | 关键问题 | 示例 |
| --- | --- | --- |
| Dependency confusion | 同名包来自错误来源 | 公开源的包替代了内部包 |
| Typosquatting | 包名拼错或看起来相近 | `numpy` 被写成 `numppy` |

**一个看来源，一个看名称。**

## 1. pip 怎样寻找依赖？

普通安装命令形式：

```bash
pip install package-name
```

这里的 `package-name` 是语法占位，不是本实验要求安装的软件包。

默认公开索引是 PyPI。组织也可能在 `pip.conf`、依赖文件或命令中使用：

```text
--extra-index-url
```

将内部仓库作为额外来源。

### 容易误解的一点

**额外索引不等于「私有源永远优先」。** 从多个来源汇集候选包时，公开源同名包可能参与选择。

原文简化为「总选最高版本」。实际还受版本约束、Python 与平台兼容性、预发行规则等影响，不能说任意高版本都一定被安装。

## 2. Dependency confusion：依赖混淆

### 原文攻击逻辑

1. 项目依赖一个内部包。
2. 安装配置同时允许公开与内部来源。
3. 攻击者在公开源注册同名包。
4. 公开包成为满足条件的优选候选。
5. 项目安装到攻击者的包，而不是预期内部包。

原文以 `99.0.0` 举例异常高版本。

**版本高只是调查线索。** 还要验证包的发布者、索引来源、依赖约束与实际解析结果。

## 3. Alex Birsan 的 2021 年研究

原文称，Alex Birsan 于 2021 年 2 月在 PyPI、npm、RubyGems 注册部分组织内部使用、但在公开源尚未注册的名称，证明对 Apple、Microsoft、PayPal 等系统的影响。

原文还列出超过 130,000 美元的漏洞奖励。本次不独立核验金额、归因和具体条件。

**学习重点：** 安装过程信任了名称和解析规则，却没有充分绑定预期来源。

## 4. Typosquatting：包名仿冒

**核心：** 利用打字错误或视觉相似，让开发者安装错误包。

### 原文示例

| 预期名称 | 原文仿冒示例 | 差别 |
| --- | --- | --- |
| `numpy` | `numppy` | 多一个 `p` |
| `requests` | `reqeusts` | 字母顺序变化 |
| `scikit-learn` | `scikitlearn` | 去掉连字符 |
| `tensorflow` | `tenserflow` | 中间字母变化 |

这些是课程示例，不等于本文已确认它们当前都在公共源中存在或都属于恶意包。

原文另提到 Fortinet 在 2023 年 1 月发现用户 `Lolip0p` 发布的 `colorslib`、`httpslib`、`libhttps` 涉及下载和执行窃密恶意软件；案例细节本次未核验。

## 🧪 5. 检查可疑依赖文件

**执行位置：** 上一任务连接后的 Linux 靶机，而不是直接在本机 PowerShell 使用 Linux 路径。

### ☐ 第一步：读取外部依赖清单

### ☐ 第二步：标出三个疑点

| 条目 | 原文判断 |
| --- | --- |
| `numppy` | 可能是 `numpy` 的仿冒 |
| `reqeusts` | 可能是 `requests` 的仿冒 |
| `internal-ml-utils==99.0.0` | 异常高版本，存在依赖混淆嫌疑 |

### ☐ 第三步：对照内部清单

```bash
cat /opt/supply-chain/dependencies/requirements_internal.txt
```

原文预期内容：

```text
torch==2.1.0
transformers==4.35.0
numpy==1.24.0
requests==2.31.0
safetensors==0.4.0
accelerate==0.24.0
```

**看两个变化：** 名称被改写，以及多出一个高版本内部包。

## 6. 原文 pip-audit 检查

课程提供的命令：

```bash
pip-audit -r /opt/supply-chain/dependencies/requirements_external.txt 2>&1
```

原文预期错误：

```text
ERROR: Could not find a version that satisfies the requirement numppy==1.24.0 (from versions: none)
ERROR: No matching distribution found for numppy==1.24.0
```

### 如何理解？

在原文实验情境中，该版本无法从可用来源解析，所以审计流程中断。

**这不能说明：**

- 文件其余条目都安全。
- 类似名字在未来或其他索引里也不存在。
- 只要安装成功，就是正确包。

原文强调：真实攻击者可能先发布包，使安装成功而不报错。

### 工具边界

`pip-audit` 主要检查已知漏洞，不是包来源或恶意行为的完整鉴定器。依赖解析与审计也可能涉及获取包元数据或构建过程，应在指定隔离实验环境中使用，不把它当作绝对无执行风险的文本扫描器。

## 7. 这节要建立什么习惯？

**安装前检查：名称是否正确、来源是否预期、版本是否合理。**

不要只看「pip 有没有报错」；能解析并安装，只说明满足了安装条件，不说明供应链可信。
