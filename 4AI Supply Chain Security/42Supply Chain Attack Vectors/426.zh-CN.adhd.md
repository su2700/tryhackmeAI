## ⚡ 30 秒速览

**攻击者不必只选一种入口，可以同时准备多条路径。**

| 向量 | 在场景中的作用 |
| --- | --- |
| 恶意 pickle | 主入口：模型加载时执行载荷 |
| 依赖混淆 | 备用入口：安装到错误来源的软件包 |
| 仓库操纵 | 信任包装：让用户愿意下载模型 |

**记忆点：阻断模型文件路径，不代表软件包路径也被阻断。**

## 1. TryTrainMe 场景时间线

### 第 1 周：同时准备模型与软件包

攻击者：

- 注册假的 Hugging Face 组织 `trustworthy-ai-lab`。
- 上传带 pickle 重建载荷的模型。
- 在 PyPI 发布同名内部包的高版本：

```text
internal-ml-utils==99.0.0
```

高版本本身不保证安装成功，还需满足版本约束、来源配置与兼容性等条件。

### 第 2 周：工程师下载并加载模型

工程师把模型用于代码审查流水线。原文描述第一次不安全加载触发载荷，并向外部域名发送 C2 beacon。

**C2：** 攻击者用于通信或控制的基础设施。

**Beacon：** 向外部发送的联络或报到请求；单次 beacon 本身不等于已证明所有后续控制能力。

### 第 3 周：依赖包成为第二个入口

原文描述常规依赖安装取得攻击者的公开包，从而建立独立于模型文件的第二条路径。

原文提及的命令形式：

```bash
pip install -r requirements.txt
```

**这行用于解释事件，不是要求你安装可疑依赖。**

### 检测阶段：异常外联

SOC 自动告警发现重复向陌生域名发出的 HTTPS 连接，随后 CEO 收到告警邮件。

日志模式应继续核对来源、业务基线与进程，不能只凭陌生域名就完成归因。

## 2. 把三条路径连起来

| 向量 | 机制 | 作用 |
| --- | --- | --- |
| Pickle payload | `__reduce__` 指向 `os.system` | 在不安全加载路径中执行命令 |
| Dependency confusion | 公开源出现 `internal-ml-utils==99.0.0` | 使依赖解析选择攻击者包 |
| Repository manipulation | 假组织与专业包装 | 提高用户下载恶意模型的可能性 |

### 备用路径为什么重要？

如果模型加载器阻止危险重建逻辑，模型入口可能失败；但依赖来源策略若仍有问题，软件包入口仍可能成功。

**因此需要逐层防御：** 来源验证、文件分析、受限加载、依赖管理、最小权限与外联监控。

## 3. 不要只修复第一个看到的问题

调查时可逐项追问：

- [ ] 除了模型文件，是否修改了依赖清单？
- [ ] 假组织只是包装，还是还有仓库写权限泄露？
- [ ] 模型和软件包是否分别留下进程或网络证据？
- [ ] 删除一个文件后，是否仍有其他入口或持久化？

这些是本中文版对场景的检查整理，不是本次已观察到的主机事实。

## ✍️ 4. 题目与答案

### Q1：创建假组织，让模型下载显得可信，属于表中的哪种向量？

```text
Repository manipulation
```

**为什么？** 操纵了模型仓库的身份与信任信号。

### Q2：如果模型加载器阻止 pickle，哪条备用路径仍可能执行代码？

```text
Dependency confusion
```

**为什么？** 可疑包经另一条安装路径进入系统，不依赖模型文件载荷成功。
