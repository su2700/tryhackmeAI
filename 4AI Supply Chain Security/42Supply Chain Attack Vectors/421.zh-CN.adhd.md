## 1. 调查背景：TryTrainMe 收到告警邮件

在前一房间 Understanding AI Supply Chains 中，课程提到 JFrog 研究者发现约 100 个恶意 Hugging Face 模型。本次不独立核验该统计。

现在，你要在实验中调查一个可疑模型。

### 邮件的中文意思

**主题：你们的系统已被入侵！**

发件人声称：通过公司的 AI 代码审查工具，已经访问服务器三周；要求检查模型加载代码，以及下载的那些看似无害的 `.pkl` 文件。

落款是一位「关心安全的研究者」。

**调查原则：** 邮件中的说法是待验证线索，不能只凭邮件就确认所有入侵细节。

## 2. 本房间要调查的四个方向

### ① 恶意模型序列化

理解 Python pickle 如何通过对象重建机制触发代码执行。

### ② 依赖混淆与包名仿冒

理解依赖安装为什么可能取得错误来源的软件包。

### ③ 模型仓库操纵

识别可疑模型来源、说明页面与仓库变更线索。

### ④ API 提供商相关风险

识别静默更新、密钥泄露以及提示模板注入等风险。

## 3. 学习目标清单

- [ ] 解释 `__reduce__` 如何参与 pickle 对象重建。
- [ ] 用 `pickletools` 分析文件，而不是直接加载可疑对象。
- [ ] 区分 dependency confusion 与 typosquatting。
- [ ] 识别模型仓库可能被操纵的迹象。
- [ ] 解释 API 模型的更新、密钥和模板风险。

## 4. 前置知识

- 完成 Understanding AI Supply Chains 房间。
- 了解 Python 变量、函数与类。
- 能使用 Linux 终端。

**Windows 使用说明：** 后续实验命令主要在 Linux 靶机中运行；可以从 Windows PowerShell / Posh 通过 SSH 连接。终端主题不会把 Linux 命令自动转换成 PowerShell 命令。
