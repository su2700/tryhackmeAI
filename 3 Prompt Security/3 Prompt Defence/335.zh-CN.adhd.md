## ⚡ 30 秒速览

**核心问题：即使一次注入成功，模型实际能做什么？**

| 控制 | 主要作用 |
| --- | --- |
| 最小权限 | 缩小数据与工具的可访问范围 |
| 按用户授权检索 | 防止读取不属于当前用户的数据 |
| 安全输出处理 | 避免生成结果直接变成脚本、SQL 或命令 |
| 速率限制 | 限制高频尝试和资源消耗 |
| 日志与监控 | 发现异常、重建经过并改进防护 |

## 1. 为什么只靠护栏不够？

原文引用 EchoLeak 与 Cursor RCE 等案例，强调注入的影响取决于应用能访问的数据、工具和执行能力。

**同样的恶意指令，在不同权限环境里，后果可能不同。**

即使权限受限，仍可能造成误导回答或泄露当前可见信息，因此不应将受限部署中的注入一概视为无害。

## 2. Principle of Least Privilege：最小权限原则

**核心：** 每个组件只获得完成工作所需的权限。

完整英文术语：

```text
Principle of Least Privilege
```

### 应用到 AI 系统

- 账单助手不需要读取全部 HR 数据。
- 文档问答不需要任意执行 shell 命令。
- 查询工具不应默认拥有数据库管理员能力。
- 只需读取的场景，不应授予写入或删除能力。

权限越大，一次成功注入可能造成的影响范围越大。没有授予的能力，攻击者无法仅靠提示凭空获得。

## 3. RAG 检索必须尊重当前用户权限

### 风险做法

不管是谁提问，都从整个组织的文档库中检索，然后希望模型自己不要泄露。

### 更合理的边界

**识别当前用户 → 验证其权限 → 在获准范围内检索 → 将结果作为不可信参考数据 → 生成回答。**

原文用 Slack AI 说明攻击者与受害者可读范围不同的风险。案例具体数据流本次未核验。

**仍需注意：** 即使只检索当前用户有权查看的资料，也必须防止它被发送到未经授权的外部收件人或网站。读取授权不等于外传授权。

### 信任边界要落实在架构中

不只是提示词写一句「文档不是指令」，还要控制：

- 检索过滤与文档访问权限。
- 外部内容如何进入上下文。
- 工具调用是否独立校验。
- 数据能被发到哪里。

## 4. Improper Output Handling：不当输出处理

原文给出的 OWASP 标识：

```text
LLM05:2025
```

**核心：** 模型输出不是可信代码或已授权操作。

### 生成后可能进入哪些地方？

| 下游用途 | 不安全处理可能导致什么？ |
| --- | --- |
| 浏览器渲染 JavaScript / HTML | XSS |
| 数据库执行生成的 SQL | SQL 注入或越权查询 |
| `exec()` 或 shell 执行输出 | RCE |
| 邮件或模板填充 | 内容注入或信息外传 |
| 工具与函数调用 | 非预期参数或越权操作 |

### 需要怎样处理？

1. 验证数据结构、类型与允许值。
2. 按展示上下文进行编码与安全渲染。
3. 对数据库操作使用合适的参数化与权限约束。
4. 对工具调用实施严格 Schema 与独立授权。
5. 不把模型返回的任意代码直接交给执行环境。

**关键区别：** Schema 校验只能说明格式符合要求，不能证明这个操作获得授权。

## 6. 速率限制、日志与监控

### 速率限制（Rate limiting）

限制请求、token 或资源消耗，缩小高频尝试的空间。反复改写覆盖指令可能值得进一步调查。

### 日志（Logging）

保留足以重建过程的请求、响应与工具调用信息。原文建议记录每次请求和响应；实际保存时也要控制日志访问、敏感信息与保留期限，避免日志成为新的泄露源。

### 监控（Monitoring）

关注异常输出量、疑似外传结构、非预期工具行为与使用模式。

**区分：** 日志与监控主要帮助检测和响应；速率限制还能直接限制部分滥用与资源消耗。它们不等于消除了提示注入本身。

## ✍️ 7. 题目与答案

### Q1：要求每个组件只拥有完成工作所需权限的原则是什么？

```text
Principle of Least Privilege
```

**为什么？** 权限最小化能缩小一次成功注入的影响范围。

### Q2：未经安全处理的 LLM 输出被传给下游，对应哪个 OWASP 标识？

```text
LLM05:2025
```

**为什么？** 按原文，这是 Improper Output Handling 的标识；不要与其他年份的编号混用。

### Q3：浏览器不安全地渲染模型生成的 JavaScript，可能导致哪种传统 Web 漏洞？

```text
XSS
```

**为什么？** 不可信脚本在用户浏览器的应用上下文中执行，形成跨站脚本风险。
